# Spec:Galaxy 灵感搜索(Galaxy Search)— 网站灵感搜索工具

**Status**: ready-for-agent
**上游文档**: [galaxy-search-PRD-v0.4.md](../../galaxy-search-PRD-v0.4.md)(业务权威,冲突以 PRD 为准)、[galaxy-search-SRS-v0.2.md](../../galaxy-search-SRS-v0.2.md)(软件需求)
**数据源**: 仓库内 `galaxy-main/`(galaxy-main 静态快照,6 类 2,708 组件)

---

## Problem Statement

galaxy 库拥有 3,000+ 社区 UI 组件,但只以按文件名的代码存档存在(如 `rare-rattlesnake-22.html`),没有预览、没有可理解的名称、没有搜索。非开发者(设计师/产品/市场)看不懂代码,想找"一个渐变颜色的按钮"时只能盲翻数百个无名 HTML 文件或放弃;轻度前端用户平均花 10–20 分钟才能找到"大概这个感觉"的组件,且拿不到可直接复用的代码。本产品面向公司/团队内部,把 galaxy 变成一个**看得见、搜得到、拿得走**的网站灵感库。

## Solution

一个 **React/Vite SPA 网站**(阿里云轻量服务器:Nginx 静态站 + Node 登录/收藏 API):用户输入一句自然语言描述(如"渐变颜色的按钮"),浏览器本地检索在 ≤1s 内返回视觉预览卡片网格;也可按"组件类型 × 风格"分类浏览。点开卡片进入详情:sandbox iframe 内组件真实交互预览(hover/点击生效)、类型/风格标签、作者与 Uiverse.io 来源链接、一键复制完整代码。登录门禁:用户名 + 密码(Supabase `users` 表 + bcrypt)→ httpOnly cookie JWT(30 天);收藏落 Supabase `favorites` 表。

数据侧:构建期对 galaxy-main 静态快照做一次全量管道——抽取元数据与风格特征 → Playwright 渲染缩略图(webp)→ 生成组件描述文档与向量索引;产物随站分发,运行时零渲染。检索为**类型词硬过滤 + 微调双塔向量打分**的混合机制;双塔不达标或不可用时自动回退规则路(规则路本身即 MVP 可用形态)。模型 = **bge-small-zh LoRA → ONNX int8(~24MB)**,浏览器端 `onnxruntime-web` 推理。

## User Stories

1. 作为一位不写代码的灵感寻求者(设计师/产品/市场),我想输入一句描述我想要的界面元素的话(如"我想要一个渐变颜色的按钮"),就能在 1 秒内看到几个"长成我描述那样"的组件视觉预览,以便快速获得设计灵感而不需要看懂代码。
2. 作为同一用户,当我的描述包含组件类型词(按钮/加载/开关/输入/复选/单选)时,我想看到结果被硬过滤到对应类型、不出现无关类型,以便结果精准命中我要的那类组件。
3. 作为同一用户,当我的描述不含任何类型词(如"炫酷发光""高级感")时,我想检索仍能返回语义相关的组件并显示命中原因,以便我能用模糊的感觉词找到东西。
4. 作为同一用户,当没有相关结果时,我不想看到空白页,而是得到"放宽描述"的提示和一个分类浏览入口,以便我换一种方式继续探索。
5. 作为同一用户,我想看到每条结果卡片上附带命中原因(类型命中 / 风格命中 / 语义相似),以便我理解"为什么是这个结果"并判断是否值得点开。
6. 作为同一用户,我想提交搜索后浏览器本地 P50 < 1.0s、P95 < 2.5s 就渲染出结果网格,以便检索快得不用等待。
7. 作为一位知道 Uiverse.io 但记不住组件名的轻度前端用户,我想点开某个结果的详情页,看到组件在 sandbox iframe 里真实交互的预览(hover/点击都生效),以便确认它就是我想要的那个感觉。
8. 作为同一用户,我想在详情页看到组件的类型/风格标签、原始作者和 Uiverse.io 来源链接,以便了解出处并跳转查看原页。
9. 作为同一用户,我想在详情页一键复制组件的完整 HTML/CSS 代码,以便直接带回我的项目改造。
10. 作为同一用户,当某个组件渲染失败没有预览图时,我想卡片仍然可见并明确标注"预览不可用",且不阻塞我复制代码,以便拿代码的价值不因预览缺失而丢失。
11. 作为同一用户,我想在详情页新标签页打开该组件的 Uiverse.io 页面,以便查看社区原帖或获取更多上下文。
12. 作为一位不想靠描述、只想逛逛的用户,我想在首页按"组件类型 × 风格"组合筛选浏览组件,以便不描述也能逛到灵感。
13. 作为同一用户,我想看到类型筛选轴只含 6 类(按钮/加载/开关/输入/复选/单选)、没有空的分类,以及一个"更多类型即将上线"的提示位,以便知道当前边界和未来方向。
14. 作为同一用户,我想在每个筛选标签旁看到实时组件数量,以便知道每种筛选下有多少可选。
15. 作为同一用户,当我未选任何筛选时,我想按类型分区浏览(与 galaxy 目录一致),以便获得结构化的浏览起点。
16. 作为一位内部用户,我想在打开网站任意页面时若未登录被重定向到登录页,以便产品只对授权的内部同事开放。
17. 作为同一用户,我想用管理员发给我的用户名和密码登录,成功后 30 天内刷新/重开都不用再登录,以便日常使用不被登录打断。
18. 作为同一用户,当用户名或密码错误时,我想看到统一的中文提示"用户名或密码错误"(不区分哪一项错),以便不泄露账号是否存在。
19. 作为同一用户,当连续失败太多次时,我想系统短暂拒绝尝试(15 分钟),以便防止密码被爆破。
20. 作为内部管理员,我想直接在 Supabase Table Editor 里给同事建号(用户名 + bcrypt 密码哈希),以便控制使用准入而不需要开发注册/管理界面。
21. 作为一位收藏型用户,我想在详情页收藏/取消收藏组件,并在收藏视图里按卡片网格回看,以便把灵感沉淀下来(P1,收尾阶段)。
22. 作为内部用户,我想在双塔模型缺失或加载失败时应用自动回退到规则路检索且界面不报错,以便搜索功能永不整体不可用。
23. 作为内部用户,我想在无结果时检索自动给出分类浏览入口而不是死胡同,以便 rollback 场景下体验仍有出路。
24. 作为内部用户,当静态索引/向量加载失败或检索不可用时,我想界面提示刷新并自动降级为纯分类浏览,以便快速自愈。
25. 作为构建工程师,我想对 galaxy-main 全部 2,708 个组件跑通数据抽取(兼容元数据注释在文件头与 `<style>` 内两种位置),以便产出完整组件记录。
26. 作为构建工程师,我想用构建期批量渲染把每个组件截成缩略图 webp(433 个 Tailwind 组件注入 Tailwind 运行时后渲染),以便运行时零渲染即可展示预览。
27. 作为构建工程师,我想渲染失败的组件被标记为预览不可用但不阻塞管道,并输出覆盖率统计,以便守住 ≥85% 的发布门槛并做降级。
28. 作为构建工程师,我想特征抽取器(风格标签:gradient/neon/glassmorphism/neumorphism/animated/dark/3D/minimal 等 + 颜色/圆角/动画结构化特征)同时供规则路检索、合成训练数据与风格分类轴三方共用,以便特征词典只维护一份。
29. 作为构建工程师,我想管道可重跑、幂等(输入不变输出不变)并带 schema 版本号,以便产物可复现、可升级。
30. 作为训练负责人,我想用程序化合成的 1–3 万对 (query, 组件) 正负样本在云 GPU 上对 **bge-small-zh** 做 LoRA 微调(仅微调、不从头训练),以便得到 query/组件双塔编码器。
31. 作为训练负责人,我想把微调后的模型合并 LoRA → 导出 ONNX → int8 量化(~24MB),并能在浏览器 `onnxruntime-web` 加载运行,以便网站端零服务器推理。
32. 作为训练负责人,我想把 50 条人工评测集单独存放、不进训练集,并可在脚本上跑"规则路 / 现成 bge 基座 / 微调双塔"三路对照、输出各类 Top-5 相关率,以便用双门槛(绝对线 + 相对优势 ≥10pp)验收是否切双塔。
33. 作为验收人,我想看到检索质量按类分层把关(Buttons 大类 ≥80% Top-5;Radio-buttons/Checkboxes 等小类 ≥70%),以便小类召回不被大类淹没(Buttons 占 6 类 45%)。
34. 作为内部用户,我想看到抽象风格描述(如"赛博朋克感觉的按钮""高级感")也能被评测覆盖,以便抽象 query 不是检索盲区。
35. 作为产品负责人,我想看到无结果 query 占比 < 5%、搜索后点击预览率 ≥ 50%、详情页复制/跳转率 ≥ 25%、7 日回头率 ≥ 15%,以便验证产品价值(发布后 90 天北星:单会话找到并打开 ≥3 个符合想法的预览)。
36. 作为内部用户,我想首次打开网站(含 ~24MB 模型下载)在 ≥10Mbps 网络下 ≤5s 内可搜索、二次访问 ≤2s,以便办公网络下体验达标。
37. 作为内部用户,我想在 Chrome/Edge 最新两版上界面正常、中文无乱码,以便日常浏览器里顺畅使用。
38. 作为安全负责人,我想组件 HTML 预览在 sandbox iframe 中隔离加载(禁远程内容、禁脚本越权),以便恶意组件代码不触及登录态与用户数据。
39. 作为隐私敏感用户,我想密码以 bcrypt 哈希存储、登录态走 httpOnly cookie、前端 JS 无法读取,且服务端不采集任何使用行为,以便放心使用。

## Implementation Decisions

以下决策来自 PRD v0.4(§5/§6/§8.E)与 SRS v0.2,工程实现须遵循;均为模块/接口/架构级描述,不含具体文件路径。

- **产品形态 = Web 网站(React/Vite SPA),废弃桌面版**:不做 Electron、不做移动端/小程序。检索/推理/浏览全部在浏览器本地;服务器只做静态下发与登录/收藏两个接口。
- **部署 = 阿里云轻量服务器(2核2G,~¥68/年)**:Nginx 静态站(页面、预览图、向量、模型 ONNX)+ Node API(`/api/login`、`/api/favorites`)。上线地址 `http://公网IP:8080`(免备案、非标准端口);备案域名 + HTTPS 为后续平滑升级,服务器不变。安全组只放行公司出口 IP + 8080 端口。
- **前端主工程 = Node.js/TypeScript + React + Vite**,不引入 Python 组件(本机无 python/docker 是硬约束);Python 生态仅存在于云端训练环境,与主工程分离。
- **检索与推理 = 浏览器端**:`onnxruntime-web` 加载 bge-small-zh ONNX int8(~24MB,强缓存);query 编码(50–150ms)+ 2,708×512 向量暴力余弦(<10ms)。组件向量离线预计算为 `vectors.bin`,行序与 `components.json` 一致。
- **混合检索**:query 先做类型词检测——命中类型词表(按钮/按键/button/btn → Buttons,加载/转圈/spinner → loaders,开关/toggle/switch → Toggle-switches,输入/input/文本框 → Inputs,复选/checkbox/勾选 → Checkboxes,单选/radio → Radio-buttons;O1 Spike 扩充同义词)则在该目录内硬过滤;再对候选做向量打分(双塔或规则特征);无类型词则全库 6 类打分。
- **检索服务为单一内部契约**:`search(query) → [{component, score, reason}]`(reason 说明类型/风格/语义命中);检索库与 React UI 解耦(浏览器端独立模块),不依赖 DOM 即可调用。分类浏览 = 对同一索引的 `filter(type × style)` 查询。
- **降级链**:双塔缺失/加载失败/未达标 → 自动回退规则路(类型硬过滤 + 风格词典/特征匹配),界面无感知;检索不可用时降级为纯分类浏览。双塔为增强项,规则路先落地即 MVP 可用形态,验收不过不阻塞发布。
- **微调双塔(query 编码器 + 组件描述编码器)**:基座锁定 **bge-small-zh(24M 参数,512 维)** + LoRA,仅微调不从头训练;合并 LoRA → ONNX → int8(~24MB)。组件侧向量在训练环境批量生成后离线预计算、随站分发;线上只跑 query 编码 + 全库余弦打分。
- **训练数据**:程序化合成打底——中文风格/颜色/形状词典 × 代码可判特征 → 1–3 万对 (query, 组件) 正负样本,tags 增强;人工评测集 50 条(PRD §8.B 按类配比 + ≥10 条纯语义/抽象 query)只做验收、不进训练。算力:按量云 GPU 数小时或 Kaggle/Colab。
- **特征抽取器 = 核心组件,一器三用**:规则层检索、合成训练数据生成、风格分类轴共享同一份"代码可判特征"(词典/正则只维护一份)。元数据注释解析须兼容文件头与 `<style>` 内两种位置;组件 ID = 文件名(去 `.html`)。
- **构建期渲染**:Playwright(headless Chromium)全量渲染 2,708 个为默认态缩略图 webp;433 个无 `<style>` 的 Tailwind 纯类名组件先注入 Tailwind 运行时再渲染;产物静态分发,运行时零渲染。渲染失败标记 `preview_available=false` 不阻塞管道;发布 gate = 覆盖率 ≥85%,失败项降级"仅代码"卡片。详情页 = **sandbox iframe 加载原始 HTML 的可交互预览**(禁远程内容、禁脚本越权、仅同源静态文件)。
- **数据源静态化**:galaxy-main 快照随站分发,不抓官网、不更新;数据不增长的触发条件(Cards 等 5 类扩展或确有增量需求)另立项。
- **构建期产物契约**(只读,随站分发):`components.json`(每项 { id, type, file, author, tags[], styles[], colors[], rounded, animated, hasJs, previewAvailable, descriptionDoc, sourceUrl })、`vectors.bin`(float32 矩阵,行序与 components.json 一致,512 维)、`images/{type}/{id}.webp`、`model/model_int8.onnx`(~24MB)、`meta.json`(schema 版本/生成时间/覆盖率/模型版本与是否启用)、`type-lexicon.json`(类型词表)、风格词典。产物带 schema 版本号,不兼容变更须升版本。
- **登录门禁(用户表登录)**:`POST /api/login` → 服务端查 Supabase `users`(bcrypt 校验)→ 签发 httpOnly cookie JWT(30 天,HS256,sub=user_id,密钥在服务器环境变量)。连续失败 ≥5 次锁 15 分钟(429)。无注册/找回;管理员在 Supabase Table Editor 建号。浏览器不直连 Supabase,service role key 仅存服务器。
- **收藏**:`GET/POST/DELETE /api/favorites`,服务端从 JWT 解析 user_id 后读写 Supabase `favorites`(primary key(user_id, component_id))。收藏为 P1(收尾阶段)。
- **Supabase 连接约束**:Node 用 Session Pooler(`*.pooler.supabase.com:6543`,transaction 模式)+ 连接池(size 3–5);服务器每日一次心跳 `SELECT 1` 防免费版 7 天休眠;接受跨境延迟 0.7–1.2s/次(仅登录与收藏)。
- **Uiverse.io 来源链接**:slug 构建期从源数据/注释解析,缺失用仓库文件名兜底(`https://uiverse.io/components/{slug}`);详情页强制展示作者与来源(D8)。
- **范围红线**:搜索/筛选仅覆盖 6 类(Buttons 1,231 / loaders 718 / Toggle-switches 260 / Inputs 226 / Checkboxes 171 / Radio-buttons 102);Cards/Forms/Patterns/Tooltips/Notifications 本期不做,界面提供"更多类型即将上线"提示位。

## Testing Decisions

**好测试的定义**:只测**外部可观察行为**——用户能感知的结果与 PRD/SRS 的可验收指标(返回了什么、顺序、命中原因、降级表现、耗时、覆盖率),不测内部实现细节(不 mock 断言向量怎么算、不测私有函数)。验收标准即测试断言:有结果率、Top-5 相关率(分大类/小类门槛)、预览点击、耗时 P50/P95、渲染覆盖率 ≥85%。

**Seam A — 检索核心(主 seam,绝大多数业务行为在此测)**:把"索引加载 + `search(query)` + `filter(type×style)` + 双塔/规则路切换"做成与 React 无关的浏览器端 TS 库,headless(node 环境,模型以 mock/规则路为主)直接调用。所有 P0 用户故事(登录除外)的行为都流经此边界。测试用**小型 fixture 语料**(从 galaxy-main 按 6 类抽样,刻意覆盖边界:注释在文件头的、注释在 `<style>` 内的、无 `<style>` 的 Tailwind 组件、含 JS 的、含 @keyframes 的),断言:
- 类型词命中 → 结果集合被硬过滤到该类型且不含无关类型(用户故事 2);
- 无类型词 → 跨类语义结果 + reason 正确(用户故事 3);
- 空结果 → 触发放宽引导而非空页(用户故事 4/23);
- 每结果带 reason(用户故事 5);
- 双塔模型文件缺失/加载失败 → 同一调用自动走规则路且结果非空、无异常(用户故事 22);
- 风格轴标签与计数来自构建期产物、无空分类(用户故事 13/14);
- 全部断言确定性(golden 可复现),不依赖网络。
**Seam B — 离线评测 harness(既有验收机制,保留)**:脚本化跑 PRD §8.B 的 50 条人工评测集 × 三路(规则路 / 现成 bge 基座 / 微调双塔),输出 Top-5 相关率;断言双门槛(Buttons ≥80%、小类 ≥70% 绝对线;双塔较规则路 ≥10pp 相对优势线)决定是否切双塔(SRS NFR-11 已定义此可测试性需求)。本 seam 覆盖用户故事 30–33 的质量验收。
**登录/收藏 API 测试**:按 SRS §6.1 契约断言——正确凭据 → 200 + httpOnly cookie;错误凭据 → 401 且不区分用户名/密码;连续失败 ≥5 次 → 429;无/过期 JWT → 401;收藏增删查按 user_id 隔离(用户故事 16–21)。用 Supabase 测试库(或本地 Postgres 同 schema)跑,不依赖生产库。
**构建期管道测试**:幂等/可重跑(golden 输出:输入不变输出不变,FR-7.7)、渲染覆盖率统计与 ≥85% gate、失败降级标记(用户故事 25–27)。渲染器只做抽样集成断言,不做逐组件单元测试。模型导出链:bge-small-zh LoRA 合并 → ONNX → int8 可被 onnxruntime-web 加载(用户故事 31)。
**UI 层:冒烟测试即可(Playwright)**:登录 → 搜索 → 详情 → 复制代码的主流程可走通;未登录重定向到登录页;业务细节不在此层重复测试(行为已在 Seam A 覆盖)。首屏/搜索耗时以 Playwright 实测记录(用户故事 36)。
**Prior art**:本仓库为 0→1 无既有测试;测试框架与 runner 由实现方在 Spike 确定(倾向 vitest 单仓库配置),Seam A/B 均需可无头运行(CI/本地一键执行)。

## Out of Scope

- 桌面版(Electron)、移动端 App、小程序
- 账号注册/找回、飞书/第三方登录、激活码
- 官网抓取与数据更新(galaxy-main 静态快照即终态)
- Cards/Forms/Patterns/Tooltips/Notifications 5 类(1,094 组件)的搜索与浏览
- 可视化定制/样式编辑器、高精度个性化推荐(相似组件 = 同类别 + 向量邻近即可)
- 100% 渲染覆盖率(≥85% 即发布)
- ICP 备案与自定义域名(本期 `http://IP:8080` 内部分发;备案为后续项)
- 强安全(公网对公众运营的合规/防护;本期内部分发 + 安全组白名单)
- 现成 embedding API 作为主力检索(仅作为三路对照中的一路基线)
- 服务端模型推理(推理固定在浏览器端)
